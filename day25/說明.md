# Day 25:受擊震動——Day 17 的伏筆回收

## 為什麼要做這個

Day 24 加了反擊之後,一個回合裡發生兩件事:勇者打小怪、小怪打勇者。但畫面上只看到兩個數字同時變 —— **玩家看不出剛剛是誰被打了**。

所以震動不是裝飾,是**功能性回饋**。它回答的問題是「剛剛發生在誰身上」。

這也呼應 Day 17 的結論:**動畫用在表現層可以,用在規則層會破壞回合制**。震動不影響任何規則,只是讓看不見的事變得看得見。

## CSS 動畫的基本寫法

```css
@keyframes shake {
  0%, 100% { transform: translateX(0); }
  15%      { transform: translateX(-8px); }
  30%      { transform: translateX(7px); }
  45%      { transform: translateX(-5px); }
  60%      { transform: translateX(4px); }
  75%      { transform: translateX(-2px); }
}

.fighter.shake {
  animation: shake 0.35s ease-in-out;
}
```

`@keyframes` 是「動畫的劇本」:百分比代表「播到幾成的時候,長什麼樣子」。幅度我刻意讓它**越來越小**,模擬被打之後的餘震。

`transform: translateX()` 是水平位移。用 `transform` 而不是改 `left`,是因為 `transform` 不會影響版面計算,瀏覽器跑起來比較順。

**一個坑**:`transform` 對 `inline` 元素無效。血量數字是 `<span>`(預設 inline),所以 CSS 裡要先加 `display: inline-block` 才動得起來。

## 今天的重點:動畫不會重播

這是我原本沒想到的問題。

```js
enemyBox.classList.add("shake");   // 第一下:動了
enemyBox.classList.add("shake");   // 第二下:什麼都沒發生
```

因為元素**已經有這個 class 了**,再加一次對 CSS 來說「狀態沒變」,動畫不會重新開始。所以連續攻擊時,只有第一下看得到效果。

標準解法是「先移除 → 強迫重繪 → 再加上」:

```js
function playEffect(el, className) {
  el.classList.remove(className);
  void el.offsetWidth;        // ← 關鍵的一行
  el.classList.add(className);
}
```

中間那行看起來完全莫名其妙:**讀取一個寬度,然後把結果丟掉**(`void` 的意思就是「執行它但不要這個值」)。

它的作用是:**逼瀏覽器把前面的移除動作真的算完**。

瀏覽器為了效能,會把連續的樣式修改累積起來一次處理 —— 如果沒有這一行,`remove` 和 `add` 會被合併成「什麼都沒變」。而「讀取版面資訊」(寬度、高度、位置)會強迫它立刻結算,因為它必須給你正確的數字。

這個技巧在前端有個名字叫 **強制重排(force reflow)**,是很多動畫函式庫內部都在用的手法。

## 無障礙:有些人不該看到動畫

```css
@media (prefers-reduced-motion: reduce) {
  .fighter.shake,
  .fighter-hp.flash,
  .hp-fill {
    animation: none;
    transition: none;
  }
}
```

有些人對畫面晃動敏感(暈眩、前庭功能異常、某些類型的偏頭痛),作業系統有一個「**減少動態效果**」的設定。這段 CSS 的意思是:當使用者開了那個設定,就關掉所有動畫。

**資訊照樣看得到,只是不動。** 這是前端無障礙的基本功之一,而且從測試角度看,它是一個「很少人會測,但確實存在的使用情境」。

Windows 的設定在「設定 → 協助工具 → 視覺效果 → 動畫效果」。想測試的話可以開開看。

## 你要做的測試

**測試 1:分辨得出是誰被打了嗎?**
打幾回合,不要看訊息文字,只看畫面 —— 你能不能只憑震動就知道剛剛誰受傷?

**測試 2:連續快速點擊**
用力連點攻擊按鈕。每一下都有震動嗎?還是只有第一下?
(這是驗證 `void el.offsetWidth` 有沒有生效。想看對照組的話,把那一行註解掉再試一次。)

**測試 3:把震動幅度調大**
`translateX(-8px)` 改成 `-30px` 或更大,跑跑看。會發生什麼事?畫面有沒有出現不該出現的東西?

**測試 4:關掉動畫**
打開系統的「減少動態效果」,重新整理,確認動畫真的停了、而且遊戲照樣能玩。
