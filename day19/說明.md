# Day 19:非同步入門——「未來會有結果」的承諾

## 為什麼需要這個

Day 17 你已經摸到門了:`setTimeout` 預約一件事,程式不會停下來等。那個「排到待辦清單最後面」的機制,今天變成主角。

現實中有些事**天生就要等**:
- 跟伺服器要資料(網路來回要時間)
- 讀取一個大檔案
- 等使用者回應

如果程式「停下來等」,整個畫面會卡死(Day 7 那次的教訓)。所以 JS 的做法是:**先去做別的事,等結果來了再回頭處理**。這就是**非同步(asynchronous)**。

## 三個階段的寫法

### 階段一:回呼函式(callback)

「做完之後,執行我給你的這個函式」:

```js
setTimeout(() => {
  console.log("一秒後");
}, 1000);
```

問題是:如果一件事要接著一件事,就會越縮越裡面 —— 這叫**回呼地獄(callback hell)**。

### 階段二:Promise

Promise 是「一個**未來會有結果**的承諾」。它有三種狀態:

| 狀態 | 意思 |
|---|---|
| pending | 還在處理中 |
| fulfilled | 成功了,有結果 |
| rejected | 失敗了,有原因 |

```js
const p = new Promise((resolve, reject) => {
  // resolve(值) = 承諾兌現
  // reject(原因) = 承諾跳票
});

p.then(結果 => { ... })      // 成功時
 .catch(錯誤 => { ... });    // 失敗時
```

比喻:**點餐拿到的號碼牌**。你拿到的不是食物,是「等一下會有食物」的憑證。你可以先去坐下(程式繼續跑),叫號了再回來拿。

(注意:這跟 Day 17 的 `setInterval` 號碼牌不同 —— 那個是「拆彈編號」,這個是「未來會兌現的憑證」。)

### 階段三:async / await

`.then()` 串多了還是會很長。`async/await` 讓非同步的程式**讀起來像同步**:

```js
async function 流程() {
  const 結果 = await 某個Promise;   // 等它完成,再往下
  console.log(結果);
}
```

`await` 只能寫在 `async` 函式裡面。它看起來像「停下來等」,但**它只暫停這個函式,不會卡住整個網頁** —— 這是關鍵差別。
