# Day 20:localStorage——讓資料「關掉再開還在」

## 目前的問題

重新整理頁面,一切歸零。名字沒了、回合數沒了、紀錄沒了。因為所有資料都存在**記憶體**裡,關掉就消失。

`localStorage` 是**瀏覽器提供的小型倉庫**:存進去的東西,關掉瀏覽器、重開電腦都還在(除非使用者主動清除)。

## 四個方法

```js
localStorage.setItem("key", "value");   // 存
localStorage.getItem("key");            // 讀(沒有的話回傳 null)
localStorage.removeItem("key");         // 刪一筆
localStorage.clear();                   // 全部清空
```

## 最大的坑:它只能存字串

這是今天一定要親手撞一次的東西。存物件進去,拿出來會變成 `"[object Object]"` —— **資料還在嗎?不在了,它被字串化成一坨無意義的文字。**

解法是 Day 6 就見過的老朋友:

```js
localStorage.setItem("hero", JSON.stringify(物件));   // 物件 → 字串
const hero = JSON.parse(localStorage.getItem("hero")); // 字串 → 物件
```

`JSON.stringify` 你在 Day 6 用過(當時是為了凍結陣列快照),今天它有了第二個用途。

## 第二個坑:第一次玩沒有資料

`getItem` 找不到資料時回傳 **`null`**(Day 10 遇過的老朋友)。直接拿去用會出事:

```js
const best = localStorage.getItem("bestTurn");   // 第一次:null
console.log(best + 1);                            // "null1" 或 NaN
```

所以一定要處理「沒有紀錄」的情況。

## 第三個坑:存進去的數字,拿出來是字串

```js
localStorage.setItem("turn", 5);
const t = localStorage.getItem("turn");
console.log(t, typeof t);        // "5" string ← 變字串了!
console.log(t + 1);              // "51" ← Day 15 的坑又來了
console.log(Number(t) + 1);      // 6
```

## 在哪裡看得到存了什麼

DevTools → **應用程式(Application)** 分頁 → 左側 **本機儲存空間(Local Storage)** → 點你的網址。可以直接看到所有 key/value,也可以手動修改或刪除。

**QA 觀點**:玩家可以在這裡直接改分數。所以 localStorage **不能用來存任何需要防作弊的東西** —— 它是「方便」不是「安全」。這跟 Day 15 的 `maxlength` 是同一個道理。
感覺這功能在我的遊戲中沒有地方好用
這功能應該是做登入網站後會獲得一個key 只要這個key沒過期就不需要重新登入
但他可以被使用者更改所以他既不能記錄回合數 也不能記錄血量攻擊力防禦力 最多記錄輸入的勇者名稱(被改了無傷大雅)

## 跑之前先想一個 QA 問題

「最少回合」的紀錄,**第一次玩的時候該存什麼?**
- 存 0?那之後永遠打不破(沒有人能用 0 回合贏)
- 存 999?看起來很怪
- 不存,判斷 null?

如果設定是玩家必須至少通關過一次才能進行(+看到)挑戰那選999應該沒關係 ->第一次記錄會取代999
但最好還是寫 null為初始值未來有問題才不會誤判

三種都能動,但哪一種最不容易出錯?這是今天的原創填空點。
