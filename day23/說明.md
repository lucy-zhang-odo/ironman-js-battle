# Day 23:專案骨架——從練習檔變成一個「專案」

前面 22 天,每天都是一個 `dayXX.html`,所有東西擠在一個檔案裡。今天開始做正式作品,第一件事是**把它拆開**。

## 一、為什麼要拆檔案

目前的 `day20.html` 已經 200 多行,HTML、CSS、JS 混在一起。問題:

- 想調顏色,要在一堆 JS 裡找 `<style>`
- 想改邏輯,要捲過一堆 HTML
- 之後檔案只會更長

正式專案的標準結構是三個檔案:

```
day23/
├── index.html    ← 骨架:畫面上有哪些東西
├── style.css     ← 外觀:長什麼樣子
└── game.js       ← 邏輯:怎麼運作
```

這就是 Day 14 說的「外觀歸 CSS,邏輯歸 JS」,現在連檔案都分開了。

## 二、怎麼連起來

```html
<head>
  <link rel="stylesheet" href="style.css">   <!-- 接上 CSS -->
</head>
<body>
  ...
  <script src="game.js"></script>            <!-- 接上 JS -->
</body>
```

兩個重點:
- `<link>` 放在 `<head>`:樣式要早點載入,不然畫面會先閃一下沒樣式的版本
- `<script src>` 放在 `</body>` 之前:**Day 10 的教訓** —— JS 要等元素都建立好才能抓到它們

## 三、為什麼檔名叫 `index.html`

網頁伺服器的預設規則:**當有人只輸入資料夾網址,伺服器會自動找 `index.html`**。

之後部署到 GitHub Pages,網址會是 `https://你的帳號.github.io/ironman-js-battle/`,不用在後面加檔名 —— 前提是檔案叫 `index.html`。

## 四、今天的 HTML 結構設計

我把畫面分成幾個區塊,每個區塊有明確職責:

| 區塊 | 用途 |
|---|---|
| `#setup` | 開場:輸入名字、開始按鈕 |
| `#battle` | 戰鬥區:雙方血條、血量數字 |
| `#log` | 戰鬥訊息 |
| `#controls` | 操作按鈕:攻擊、再戰 |
| `#record` | 最少回合紀錄 |

**血條**是今天的新東西,原理很單純:

```html
<div class="hp-bar">
  <div class="hp-fill" id="enemyHpFill"></div>
</div>
```

外層是固定寬度的軌道,內層是實際血量。用 JS 改內層的寬度百分比:

```js
const percent = (state.enemy.hp / state.enemy.maxHp) * 100;
enemyHpFill.style.width = percent + "%";
```

**這就是 Day 14 的 `maxHp` 真正發揮作用的地方** —— 沒有滿血值,算不出百分比。
